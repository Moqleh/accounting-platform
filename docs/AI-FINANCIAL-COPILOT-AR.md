# المساعد المالي الذكي — AI Financial Copilot

## الهدف
إضافة مساعد تحليلي مالي احترافي إلى منصة المحاسبة يساعد متخذ القرار على فهم بيانات الشركة بسرعة، مع المحافظة على الدقة المحاسبية والصلاحيات والعزل بين الشركات.

المساعد **للقراءة والتحليل فقط في المرحلة الأولى**. لا ينشئ ولا يرحّل ولا يعدّل ولا يحذف قيودًا أو فواتير أو سندات أو حسابات أو مستخدمين.

## من يحق له استخدامه؟
الميزة متاحة فقط داخل الشركة الحالية للأدوار التالية:

- `OWNER` — صاحب الشركة.
- `FINANCE_MANAGER` — المدير المالي.

أي مستخدم آخر يجب أن يحصل على `403 Forbidden` من الـ API نفسه. إخفاء زر المساعد من الواجهة ليس حماية كافية.

> يجب مطابقة أسماء الأدوار أعلاه مع enum/roles الفعلية في قاعدة البيانات قبل التنفيذ، وعدم الاعتماد على أسماء مفترضة.

## مبدأ الدقة
لا يُسمح للنموذج اللغوي باختراع الأرقام أو حساب الأرصدة من نص حر. الأرقام تُحسب أولًا داخل خدمات النظام/SQL الموثوقة، ثم يُعطى النموذج Dataset صغيرًا ومنظمًا لشرح النتائج فقط.

كل إجابة مالية يجب أن تحتوي على:

1. الفترة الزمنية المستخدمة.
2. العملة.
3. الأرقام الأساسية التي بُني عليها الاستنتاج.
4. مصدر البيانات داخل النظام (مثل المبيعات، الأستاذ العام، الذمم، البنوك).
5. تنبيه واضح إذا كانت البيانات ناقصة أو لا تكفي للاستنتاج.

## المعمارية

```text
Authorized User
      |
      v
Accounting Web UI
      |
      v
POST /api/ai/ask
      |
      +--> JWT authentication
      +--> current company membership
      +--> OWNER / FINANCE_MANAGER authorization
      +--> question allowlist / intent classification
      +--> deterministic financial query service
      +--> tenant/company scoped database query
      +--> structured financial facts
      +--> AI explanation layer
      +--> response with evidence + period + currency
```

لا يوجد اتصال مباشر بين نموذج AI وقاعدة البيانات. النموذج لا يحصل على SQL credentials ولا JWT secret ولا أسرار الخادم.

## أنواع الأسئلة في الإصدار الأول

### لوحة الإدارة التنفيذية
- ما صافي المبيعات هذا الشهر؟
- قارن المبيعات بالشهر السابق أو نفس الشهر من السنة السابقة.
- ما إجمالي المشتريات؟
- ما اتجاه التدفق النقدي؟
- ما أرصدة النقد والبنوك؟

### العملاء والتحصيل
- كم إجمالي الذمم المدينة؟
- من العملاء الأعلى مديونية؟
- ما الديون المتأخرة حسب شرائح الأعمار؟
- ما المبالغ المستحقة خلال 7/30 يومًا؟

### الموردون
- كم إجمالي الذمم الدائنة؟
- ما المدفوعات القادمة؟
- من أكبر الموردين حسب المشتريات أو الرصيد؟

### الربحية
- مقارنة الإيرادات والتكاليف والمصروفات.
- تغير هامش الربح بين فترتين.
- تحديد البنود التي ساهمت رقميًا في التغير، دون ادعاء سبب غير مثبت.

### الرقابة المالية
- قيود غير متوازنة إن وجدت.
- فواتير محتمل تكرارها وفق قواعد محددة.
- حركات أو مصروفات غير معتادة وفق threshold/statistical rules واضحة.
- فروقات بنكية أو عناصر غير مسواة عندما تتوفر بيانات المطابقة.

## تصميم الإجابة

مثال:

**السؤال:** لماذا انخفض هامش الربح هذا الشهر؟

**الإجابة:**
- الفترة: 1–30 سبتمبر 2026.
- العملة: SAR.
- المبيعات: 420,000.
- تكلفة المبيعات: 315,000.
- هامش الربح: 25.0% مقابل 31.4% في الفترة المقارنة.
- أكبر تغير رقمي: تكلفة المبيعات ارتفعت بمقدار ...

**القراءة:** البيانات تظهر تزامن انخفاض الهامش مع ارتفاع نسبة تكلفة المبيعات. لا يصف المساعد ذلك كسبب مؤكد ما لم تتوفر بيانات تفصيلية تدعمه.

**المصادر:** Sales / General Ledger / Purchases.

## الحماية

### Authorization
- JWT إلزامي.
- استخراج `userId` من JWT فقط.
- التحقق من membership للشركة المطلوبة في كل طلب.
- التحقق server-side من الدور.
- ممنوع قبول `role` أو `userId` من body كدليل صلاحية.

### Tenant isolation
كل query يجب أن تكون مقيدة بـ `companyId` الذي تم التحقق منه. لا يسمح للنموذج باختيار companyId ولا بكتابة SQL.

### Privacy
لا ترسل إلى مزود AI:
- كلمات المرور أو password hashes.
- JWT/access tokens.
- database credentials.
- أسرار البيئة.
- بيانات لا يحتاجها السؤال.

استخدم aggregation/minimization. عند سؤال عن إجمالي المبيعات، أرسل الإجمالي والفترة بدل إرسال جميع الفواتير.

### Prompt injection
تعامل مع السؤال والنصوص المخزنة في قاعدة البيانات كبيانات غير موثوقة. لا تسمح لها بتغيير system policy أو طلب أسرار أو تجاوز الشركة/الدور.

### Rate limiting
طبّق حدًا على `/api/ai/ask` لكل user + company، مع حد يومي/زمني قابل للضبط، ولا تعتمد على الواجهة لمنع الإساءة.

### Audit log
سجّل:
- userId
- companyId
- timestamp
- intent
- الفترة المطلوبة
- معرف الطلب
- نجاح/فشل
- زمن التنفيذ

يفضل عدم تخزين نص السؤال الكامل افتراضيًا إذا كان قد يحتوي معلومات حساسة؛ يمكن تخزين hash/metadata أو سياسة retention قصيرة حسب الحاجة.

## Guard مقترح
أنشئ `AiFinancialAccessGuard` بعد `JwtAuthGuard`:

1. يقرأ `req.user.sub`.
2. يحدد الشركة الحالية من سياق موثوق.
3. يبحث عن membership نشطة.
4. يسمح فقط للأدوار الفعلية التي تقابل صاحب الشركة والمدير المالي.
5. يعيد 403 لباقي المستخدمين.

## API مقترح

### POST `/api/ai/ask`
Request:

```json
{
  "question": "قارن المبيعات بالشهر السابق",
  "companyId": "...",
  "language": "ar"
}
```

`companyId` في الطلب ليس تفويضًا؛ يجب التحقق من membership له server-side.

Response:

```json
{
  "answer": "...",
  "period": {"from":"2026-09-01","to":"2026-09-30"},
  "currency": "SAR",
  "facts": [
    {"label":"sales","value":420000},
    {"label":"previousSales","value":390000}
  ],
  "sources": ["sales"],
  "warnings": [],
  "requestId": "..."
}
```

## طبقة الأدوات المالية
بدل إعطاء النموذج وصولًا حرًا للبيانات، نعرّف functions داخلية محددة مثل:

- `getSalesSummary(companyId, from, to)`
- `getPurchasesSummary(companyId, from, to)`
- `getReceivablesAging(companyId, asOf)`
- `getPayablesAging(companyId, asOf)`
- `getCashAndBankBalances(companyId, asOf)`
- `getProfitabilityComparison(companyId, periodA, periodB)`
- `getTopCustomersByReceivable(companyId, asOf, limit)`
- `getUpcomingPayables(companyId, days)`

هذه الخدمات مسؤولة عن الأرقام. AI مسؤول عن صياغة تفسير واضح فقط.

## مراحل التنفيذ

### المرحلة 1 — Read-only Executive Copilot
- صلاحيات OWNER / FINANCE_MANAGER فقط.
- أسئلة محددة ومقيدة.
- مبيعات، مشتريات، نقد، ذمم، ربحية.
- مصادر وأرقام وفترة في كل جواب.
- audit log + rate limiting.

### المرحلة 2 — Financial Alerts
- تنبيهات تحصيل.
- استحقاقات موردين.
- تغيرات مالية مهمة.
- anomalies بقواعد قابلة للتفسير.

### المرحلة 3 — Draft Assistant
يسمح بإنشاء **مسودة فقط** لقيد/فاتورة/تسوية. لا تصبح حركة محاسبية فعلية إلا بعد مراجعة واعتماد بشري وصلاحية مستقلة.

## قواعد غير قابلة للتجاوز
- AI لا يرحّل قيدًا تلقائيًا.
- AI لا يحذف بيانات.
- AI لا يغير صلاحيات.
- AI لا يرى شركة أخرى.
- AI لا يجيب من التخمين عندما لا توجد بيانات كافية.
- كل رقم مهم يجب أن يأتي من query/service محاسبية حتمية.
- أي إجراء مالي مستقبلي يحتاج تأكيدًا بشريًا وصلاحيات النظام المعتادة.
